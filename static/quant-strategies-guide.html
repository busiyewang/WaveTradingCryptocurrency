03十分钟跑通第一次本地研究

第 1 步 · 进入当前项目

cd /Users/wangye/YeWang/缠论

使用项目虚拟环境 .venv/bin/python。不要依赖系统是否存在 python 命令。量化命令独立于 Flask，跑研究不必先启动网页。

第 2 步 · 创建研究表并运行合成演示

.venv/bin/python -m quant init-db
.venv/bin/python -m quant demo

没有配置 DATABASE_URL 时默认写入 var/quant.db。如果已设置该变量，命令会连接指定数据库；想明确只用本地 SQLite，可针对本次命令指定：

DATABASE_URL=sqlite:///var/quant.db .venv/bin/python -m quant demo

输出 JSON 包括 run_id、status、summary、signal_timings。保留 run_id；演示没有候选并不代表程序故障。

第 3 步 · 将报告保存为文件

init-db 完成后 var 目录已存在。下方示例使用新的输出文件名；重复重定向会覆盖同名文件，重要报告请改名保存。

.venv/bin/python -m quant demo > var/demo-first-report.json
.venv/bin/python -m quant report YOUR_RUN_ID

把 YOUR_RUN_ID 替换为刚才实际输出的 ID，查询时使用同一个数据库配置。进度信息走终端标准错误，重定向文件保存的是 JSON。

第 4 步 · 检查测试

.venv/bin/python -m unittest discover -s tests -v

未提供 QUANT_TEST_DATABASE_URL 时，MySQL 集成测试会明确显示 skipped。跳过表示没有验证到 MySQL 实例，不是连接成功。

04配置 MySQL：只需要一个专用库

第一版不需要 Redis。准备独立 MySQL 8.0.16+ 数据库，表引擎为 InnoDB，字符集 utf8mb4。不要使用已有业务表所在的共享数据库做实验。

  1. 准备账号：由你或管理员创建专用数据库和账号，允许建研究表、查询、插入、更新。当前初始迁移会使用数据库会话锁；后续 ALTER 类迁移再补相应权限。
  2. 安装可选驱动：只影响量化研究的 MySQL 模式，本地 SQLite 不需要。
.venv/bin/python -m pip install -r requirements-quant.txt

在本地配置连接环境变量。下面全部是占位内容，不要原样当真实连接：

export DATABASE_URL='mysql://quant_user:YOUR_URL_ENCODED_PASSWORD@DB_HOST:3306/chan_quant'
.venv/bin/python -m quant init-db
.venv/bin/python -m quant demo

用户名或密码包含 @、:、/ 等保留字符时须 URL 编码。远程 TLS 可追加 ?ssl_ca=/absolute/path/ca.pem，代码会验证证书与主机名。优先通过本地秘密配置或服务管理器注入，不把真实连接串提交到 Git、贴入聊天或共享日志。

.env.example 是模板，不是自动生效的配置。当前程序不自动加载 .env。只修改模板文件不会改变连接；终端、后台服务和测试进程需要各自收到正确的环境变量。

要验证 MySQL 事务与迁移，请给 QUANT_TEST_DATABASE_URL 单独配置一个测试库，再运行测试命令。该测试会建表并留下测试记录，不删除已有数据。设置 DATABASE_URL 不会自动启用这项集成测试。

数据库切换不会自动复制 SQLite 历史记录。当前迁移是“建表和更新表结构”，不是“搬运两个数据库之间的数据”。

05导入真实历史：数据要覆盖同一时间轴

准备一个 JSON 文件，例如 var/history-eth.json。顶层有品种、4H 数组和 15m 数组。下面仅演示格式，这么少的 K 线会因预热不足被拒绝：

{
  "inst": "ETH-USDT-SWAP",
  "4H": [
    {"ts": 0, "o": 2000, "h": 2020, "l": 1980,
     "c": 2010, "vol": 1600, "confirm": 1}
  ],
  "15m": [
    {"ts": 0, "o": 2000, "h": 2008, "l": 1995,
     "c": 2005, "vol": 100, "confirm": 1}
  ]
}
检查项输入要求
品种只支持 BTC-USDT-SWAP、ETH-USDT-SWAP。
时间ts 为整数 UTC 毫秒开盘时间。15m 按 900000 对齐，4H 按 14400000 对齐。
顺序与连续性升序、无重复、无缺口。程序不会偷偷排序或插值补造 K 线。
确认状态confirm 必须为整数 0 或 1；最多保留最后一根未收盘 K，回放排除它。
OHLCV价格是正有限数，成交量非负，高低范围合理；不可填 NaN 或缺字段。
时间覆盖至少 40 根 4H / 80 根 15m，预热后区间重叠；4H 需覆盖全部小级别评估区间。
大小级别一致性确认来自同一合约、同一数据口径；比较重叠区间的 OHLC 与成交量聚合。当前代码尚未自动交叉校验两周期聚合一致性。

40 根 4H 相当于 160 小时，只是计算预热。做长期实验必须准备更长历史。网页单次约 1200 根小周期 K 通常不足以构成有效长期研究；研究回放默认窗口仍为 600 根，两者是独立配置。也不要将合成 demo 数据当真实行情。

.venv/bin/python -m quant replay var/history-eth.json --fee-rate 0.0005 --slippage-rate 0.0005

两项参数用比例：0.0005 = 0.05%。这是单边手续费和单次不利滑点研究假设。当前命令尚未计资金费，且没有完整订单成交模拟。

历史下载器还没有实现。欧易原始 K 线接口的数据顺序和字段形式需要转换为这里的输入协议；不要直接把原始接口响应整个保存后喂给 replay。接口字段依据 欧易行情文档。

06读懂报告：为什么程序一直观望

报告先看 status 与 summary.steps，再看候选数量及拒绝原因。查看某个信号时，把极值时间和首次锁定时间放在一起看。

报告字段正确解读
manifest配置、策略版本、源码哈希与数据哈希。比较两次结果前先核对这些是否一致。
summary.steps完成评估的小周期收盘事件数，不是全部输入 K 线数量，也不是交易笔数。
summary.candidates各方向去重后的研究候选数；没有成交、持仓和净值含义。
summary.reasons每根评估产生的最终原因计数；这是过滤流程首先遇到的原因，不是每个因子的独立失效率。
signal_timings信号的极值时间、第一次观察与第一次看到锁定的时刻；首次观察可能被回放边界截断。
结构 known_at / span_known_at / locked_at分别为初次可知、当前中枢完整跨度可知、证据锁定的事件 K 线收盘时间。蓝框起止和端点仍回溯到历史极值位置，不代表当时已知或可以成交。
pnl_available=false当前模块没有收益计算。候选增加不能直接解读为利润增加。
原因代码含义如何处理
no_active_signal最新锁定笔端点起及较新的候选中没有支持的二/三类信号;暂无锁定时看最近两条成笔。检查是否确实无 B2/B3/S2/S3；B1 或 DB/DS 不在 V4 范围。
signal_unlocked最新选中信号未锁定或锁定字段缺失。看后续收盘事件，不能在历史极值价“提前成交”。
direction_neutral_or_conflict4H 中性、结构不足或方向相反。确认大周期输入与收盘边界；正常冲突就接受观望。
away_from_structure信号极值没有接近可用 4H 结构位。检查关键位和容差，不靠随意放大阈值凑单。
structure_invalidated参考价格已越过结构止损。该点失效，等待新信号，不扩大止损挽救旧信号。
no_structure_target顺方向没有可用结构目标。无法核算合理收益空间，等待结构形成。
net_rr_below_minimum计研究费用/滑点后盈亏比不足 2。可能是确认太晚、价格太远或费用太大；当前只是重新逐根评估，不会自动挂等待价订单。
candidate_already_emitted同一信号本次回放已输出过候选。这是去重，不是丢信号；新的 run_id 会独立重新研究。
eligible_research_candidate支持的信号通过当前研究过滤。还需未来持仓风控与实际成交条件，不能视为订单已经发送。
怎样查看每根事件的细节，而不只看摘要？

当前 report 命令主要输出摘要和信号时间。完整每根决策在 quant_evaluations.snapshot_json；可在数据库客户端按 run_id 与 observed_at 查询。页面暂未对接这些记录。

SELECT observed_at, action, reason, snapshot_json
FROM quant_evaluations
WHERE run_id = '替换为实际RUN_ID'
ORDER BY observed_at;
已经锁定，为什么换一段历史或刷新后图形还可能变化？

锁定前缀的稳定性针对同一固定历史起点的数据追加。网页约 1200 根、研究默认 600 根窗口左端滚动时，初始包含方向、笔和线段起点会重算，不能承诺所有历史标注都不变。研究应保留每次观察快照，不能把最终图上的蓝框或信号回填为过去已知。

为什么第一次就看到“已经锁定”的信号？

回放在预热结束后开始记录，有些历史信号已经存在。first_observation_left_censored=true 表示更早出现时刻不可从当前范围判断，不代表信号在本次开始时才真实形成。

07有哪些策略：先从一套基线开始

当前代码只有一套 chan-b23-v4-macd-10-20-5 研究过滤器，合并支持 B2/B3/S2/S3；二类点的来源限于结构成立的趋势背驰一类点，盘整背驰和动能衰减不生成一类点及其后续二类点。下面将二类与三类拆开讲，是为了理解交易逻辑，目前命令没有独立选择这些策略的开关。其他方案是待验证候选，不是可调用成品。

V4 的指标与结构口径：

MACD 统一为 (10,20,5)：DIF=EMA10−EMA20，DEA=EMA5(DIF)，HIST=2×(DIF−DEA)。参数变化会影响指标及候选集合，面积比 <0.7 的门槛不变。

笔的两端之间含端点至少 5 根处理后 K 线，两端还须是整个区间的高低极值。未锁定尾部会保留未入选分型并回退重选；端点至少有两笔后续确认笔，且仍是待调整尾部的同类型极值，才可能锁定，不能按固定几根 K 线倒推。

每个原子中枢最多 9 笔。同首区间持续重叠的后续笔归入连续组，图上合并显示，不以九笔封顶宣布离开。三类点使用离开之前已形成的中枢，检查真实离开笔与紧接回踩笔；触边或回到中枢不成立。

主图和多级别页增加默认关闭的紫色粗线「线段」层：处理特征序列包含，无缺口分型确认，有缺口等待反向特征确认，只依赖连续已锁定笔。未锁定画虚线。中枢和信号仍按笔级近似计算，开启线段不会切换为完整递归线段中枢。

单周期、多级别与量化使用同一活跃范围：最新锁定笔端点起及较新的候选;暂无锁定时看最近两条成笔。有更新的笔锁定后旧信号才过期。量化仍选最新 B2/B3/S2/S3 且要求锁定，价格失效、方向、结构与扣费后盈亏比过滤保持有效。

V4 须与历史 V3（chan-b23-v3-strokes-centers）、V2、V1 分开记录，候选集合不可直接混合比较。报告源码指纹已包含笔、中枢、线段三个独立算法模块；先核对版本、参数与数据，再解释结果差异。

策略市场假设当前状态主要失败情形
A · 二类回调确认大级别方向延续，回调不破前低 / 反弹不过前高。V4 已纳入 B2 / S2 筛选反转继续、锁定滞后、入场过晚。
B · 三类突破回踩离开中枢后趋势延续，回踩不回中枢。V4 已纳入 B3 / S3 筛选假突破、重回中枢、缺少上方目标。
C · 背驰反转新极值伴随动能衰减，可能结束原趋势。分析已有 B1/S1；自动策略未接强趋势背了又背，过早逆势。
D · 隐藏背离中继价格保持趋势结构，但指标回调更深。分析已有；自动策略未接趋势已变、指标冲突、信号同源。
E · 收盘突破趋势确认突破历史区间后跟随趋势。只有观察提示；完整策略未实现震荡反复假突破、追单滑点。
F · 资金费率对冲在现货与永续对冲方向暴露，研究净资金费收益。无现货对冲/资金费引擎费率反转、基差、资金占用、单腿与强平风险。
STRATEGY A / IN V4

二类回调确认

做多示例：4H 多头 → 15m 已有 B1 → 后续回调笔不破该前低，形成 B2 → B2 锁定 → 靠近 4H 结构 → 目标与成本合格。

止损与退出：V4 候选止损在 B2 极值下方 0.2%；研究目标是顺方向最近结构位。未来拟在目标全部退出，真正的成交退出尚未实现。

做空：对称使用 S1→S2、4H 空头及信号高点上方缓冲。方向不明就不做。

STRATEGY B / IN V4

三类突破回踩

做多示例：向上离开 15m 中枢 → 回踩终点仍在 ZG 上方 → B3 锁定，同时满足 4H 多头与大级别结构距离条件。

止损与退出：当前止损以 B3 极值下方 0.2% 为准；不能把图上中枢边界随手当成代码止损。目标同样取顺方向最近大级别结构。

做空：向下离开后回抽仍低于 ZD，形成 S3。单根放量突破不等于三类信号。

STRATEGY C / RESEARCH IDEA

背驰反转

候选定义：有效结构背驰、价格新极值、面积比小于 0.7，等待锁定及反转确认后研究入场。

设计边界：若放开逆大级别方向限制，必须是单独的新策略版本。不能借用 V4 名称偷偷改成逆势抄底。

退出草案：以信号极值失效退出，以反向结构位为目标；若空间不足直接跳过。需要更细的趋势状态和确认滞后测试。

STRATEGY D / RESEARCH IDEA

隐藏背离中继

候选定义：多头回调低点抬高，但部分指标更低；空头反弹高点降低，但部分指标更高。沿用分析层至少三票作为研究起点。

必要条件：顺大级别、结构未破、信号锁定，并重新检查成本后收益空间；不能把三票当三个独立证据。

退出草案：回调结构失效退出，最近顺向结构目标止盈。要与纯 B2 基线比较是否增加独立价值。

STRATEGY E / RESEARCH IDEA

收盘突破趋势

候选定义：突破在决策前已知的区间或中枢，等待指定周期收盘，必要时再等回踩。比较“收盘直接跟随”和“回踩确认”应分版本。

退出草案：返回突破失效位退出，跟踪结构止损；窗口 N、成交量阈值和时间退出先固定，再做样本外测试。

代码现状：多级别页面的放量突破提示仅供观察，不可把该提示直接接入订单。

STRATEGY F / SEPARATE SYSTEM

资金费率对冲

研究示例：费率为正且预期净收益覆盖成本时，研究买现货、等额方向对冲的永续空头。两腿必须使用真实成交与资金费账本。

退出草案：净费率收益不足覆盖成本、对冲偏离或风险预算不足时退出；需处理两腿成交时差与借贷/保证金。

独立开发：现有项目只研究单腿 USDT 永续，不能通过加一个因子就获得“无风险套利”。

资金费的支付方向和结算以具体合约为准，预估费率会变化；对冲只能减少部分方向暴露。欧易资金费机制；欧易关于基差与资金费交易的机构报告。

第一阶段建议：保留 A + B 基线，分别统计信号类型。先看二类、三类在同一成本、同一时间段的表现差异，再决定拆成独立策略。避免同时上线六套、无法解释风险来源。

08如何判断策略值不值得继续

完整收益回测模块完成后，应按下面的研究流程评估。当前信号报告不能直接计算这些指标。

评价项判断方法常见误读
每笔净期望平均每笔盈亏，纳入手续费、滑点和资金费；可按初始风险 R 归一化。高胜率也可能被少数大亏抵消。
最大回撤净值从历史峰值到随后低点的最大相对跌幅；包含未平仓浮盈亏。只看已平仓资金曲线，会隐藏持仓风险。
样本数量与分布分币种、方向、类型、行情状态和时期统计；少量交易时承认不确定性。一段牛市或几笔大盈利不能证明长期稳定。
样本外表现时间顺序拆分研究、验证和最终测试；参数调整后不可继续把同一测试段当全新样本。反复调参数看到满意为止，就是在拟合历史。
成本敏感性加大滑点、提高费率、引入未成交与延迟，检查优势是否消失。用理想触价成交替代实际盘口。
执行可行性入场/退出的数量、最小张数、深度、保护和最大持仓期限。回测有信号，实盘不一定能以该价格、该数量成交。
每笔期望 = 胜率 × 平均盈利 − 败率 × 平均亏损
教学例：胜率 40%，平均盈利 2R，平均亏损 1R → 0.2R / 笔（未计额外成本）
这只是算术，不是本策略的实际测得胜率或收益。

需要进行多次策略试验时，记录所有尝试与失败版本。出现重叠持仓或较强时间相关性时，评估不能假设每笔样本相互独立。扩展到多币种时，应共享一个账户风险账本，而不是各币种分别拿满预算。

上线之前必须补齐的行为

  • 入场必须晚于信号实际可用时刻；同根 K 同触止盈止损，用细粒度重建或保守处理。
  • 写明持仓最大期限、反向信号的处理、期末未平仓如何计价，不能凭肉眼提前退出。
  • 同一订单重复事件、部分成交和撤单竞态应保持账本一致。
  • 模拟盘成交环境和实盘深度不同，模拟盈利不能代替实盘滑点验证。

09欧易模拟盘：未来接入时怎么走

本节是接入阶段操作计划，不是当前已可执行的功能。当前项目没有交易客户端、后台实时执行器或真实账户连接入口。不要把 API 密钥填进网页原型。
  1. 先完成工程前提：真实行情持续更新、完整收益回测、MySQL 对账记录和订单状态机已可用。
  2. 创建模拟交易 API Key：按欧易对应地区站点的模拟交易流程创建，与实盘密钥分离。账户可用产品及接入域名以你的账户所在站点为准。
  3. 配置后端环境：需要 Key、Secret、Passphrase 等鉴权信息；模拟请求使用 x-simulated-trading: 1。此项目目前还没有这些配置读取项。
  4. 核对账户与合约：读取账户模式、逐仓/全仓、持仓模式、合约面值、数量/价格步长和费率；不能默认所有账户设置相同。
  5. 先做订单闭环测试：委托、查询、部分成交、撤单、止损、只减仓退出、断线重连，逐项与欧易订单记录核对。
  6. 再跑策略：用相同策略版本记录信号、风控通过与拒绝原因、真实委托和成交。不要先追求收益再补账。

模拟环境需要模拟 API Key 与相应请求标记；具体接入要求以 欧易 API 文档 和 欧易 API 常见问题 为准。

持仓管理的默认原则

  • 数据过期、账户对账不一致或保护状态未知：停止新增仓位。
  • 开仓部分成交就保护对应已成交数量，不等待剩余委托全部成交。
  • 暂停策略仍维护已有止损；断网时依赖已验证的交易所保护，不能靠本机轮询作为唯一止损。
  • 下单超时先查单；欧易 clOrdId 检查不等于本地永久去重。欧易订单管理指南

实盘应在以上流程验证后用单独环境接入。密钥只授予必要的读与交易权限，不授予提现权限；持续运行使用稳定的后台服务器。此项是未来部署约束，不表示本项目已经具备这些保护。

10常见问题与日常检查表

页面能切换“模拟盘”，为什么欧易没有订单？

因为它是页面原型。所有按钮只影响本页样例，没有交易接口。真实模拟盘客户端尚未开发。

找不到 python 或依赖报错怎么办？

先进入本项目目录，再使用 .venv/bin/python。系统 Python 的依赖可能不同。MySQL 驱动单独安装 requirements-quant.txt；Flask 端口占用时直接打开已有服务，不重复启动。

为什么历史数据报“预热后时间范围没有交集”？

40 根 4H 收盘后，小级别数据已经结束，或两组数据不是同一时间范围。补齐更长历史并检查 UTC 毫秒对齐；不能只满足数组长度。

MySQL 配置了但仍写到 SQLite？

检查启动该进程的环境中是否真正设置 DATABASE_URL。当前不会自动读取 .env；另一个终端或服务管理器不会自动继承你在当前终端设置的值。

数据库提示迁移校验和变化？

已应用的迁移文件被修改了。应新增迁移版本，不删除有价值的研究库来绕过检查，也不要随意手工更改迁移记录。

日亏 3% 已经会自动停手吗？

不会。当前只是设计规则和界面样例，尚未接入持续账户权益及风险状态。独立 risk.py 只根据调用者提供的参数计算本单数量。

为什么不能把评分高的买点都买入？

评分是解释特征，不是胜率。锁定、方向、结构、成本和账户风险仍必须通过；界面仓位百分比也不能当真实资金投入比例。
