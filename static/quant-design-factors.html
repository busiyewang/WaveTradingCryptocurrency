01先明确系统做到了哪一步

目标是把“看图判断”变成有条件、有时间依据、能复查的交易流程。第一步验证信号，第二步验证成交与收益，最后才让欧易执行。

当前可用：研究基础。未来目标：交易闭环。现有命令可以回放历史 K 线、记录候选信号与拒绝原因、计算风险仓位。浏览器中的量化工作台是交互原型。完整收益回测、资金费结算、账户风控和欧易订单执行尚未实现。
能力状态你可以据此判断什么
缠论结构、背驰、二三类信号已实现判断当时的结构和候选条件；不能直接推导未来胜率。
逐根信号回放 / 快照落库已实现知道信号何时被看到、何时锁定，以及为什么被过滤。
风险张数计算独立函数测算本单数量上限；尚未与真实账户、持仓、订单相连。
MySQL / SQLite接口已写本地 SQLite 已验证；MySQL 实例集成测试需连接专用测试库。
量化工作台页面样例预览检查布局和交互；页面上的金额、信号数不是后台结果。
净值收益 / 模拟盘 / 实盘待开发目前不能给出可靠收益率，也不能自动下单。

本册中的“量化因子”指可计算的特征或条件。它们是否能预测未来收益，还需要样本外数据验证；不是列出多个指标就证明存在盈利能力。

03最重要的因子：信号何时可用

缠论买点通常标在过去的极值位置。极值出现、信号出现、信号锁定是三件不同的事。下面只是时序示意，不承诺固定延迟。

10:00 · 极值出现

价格形成一个低点，但当时不知道之后会不会继续下跌。图上锚点属于这一根 K 线。

10:30 · 首次观察

后续收盘 K 线让分型和信号成立。最新端点仍可能移动，程序记录候选但不执行。

11:15 · 首次观察到锁定

反向确认笔形成，信号满足锁定条件。只有此后才允许进一步检查入场。

11:15 之后 · 执行检查

实际成交还受行情接收、网络延迟、盘口、价格偏移和订单状态影响。回测不能回到 10:00 的最低价买入。

字段 / 规则准确含义
ts / extreme_atUTC 毫秒开盘时间；extreme_at 是信号极值所属 K 的开盘时间。
收盘事件15m：ts + 900000；4H：ts + 14400000。只取 confirm == 1 的已收盘数据。
first_observed_at本次回放开始评估后，第一次看到这个信号的时刻。
first_locked_observed_at第一次看到 locked 为 true 的时刻；未观察到则为 null。
first_observation_left_censored第一次评估时信号已经存在，无法从当前回放范围确定它更早何时出现。
大小级别对齐每个 15m 事件，只能使用当时已经收盘的 4H 前缀；缺失未来该到达的大周期数据会导致回放拒绝。
窗口与预热4H 至少 40 根，15m 至少 80 根；分别最多使用最近 600 根。预热最低值不等于足够的统计样本量。
看似“稳了”的信号，价格可能已经不划算。锁定解决的是信号时序问题，不保证盈亏比或盈利。必须在锁定后以当时参考价重新核算；量化系统正常地会因此放弃不少买点。

04结构基础：从 K 线到买卖点

以下是本项目采用的确定性定义。缠论存在不同实现口径，策略实验必须固定版本，不能在回测中途改变定义。

结构当前口径交易者怎么理解
包含处理向上取高高、向下取低低，先消除相邻 K 线包含关系。笔的长度按处理后 K 线计算，不能直接数图上的原始蜡烛。
分型与新笔顶底交替，端点之间含端点至少 5 根处理后 K；同类分型更极端则替换。最新笔端点会移动，是信号重绘的来源之一。
中枢连续三笔重叠：ZG=min(三笔高点)，ZD=max(三笔低点)，ZG>ZD；最多延伸 9 段。ZG / ZD 是当前结构边界，不能把所有历史中枢都当成同一目标。
MACDDIF=EMA10−EMA20；DEA=EMA5(DIF)；HIST=2×(DIF−DEA)。这里的柱值使用国内公式，面积比较不能混用不同 HIST 定义。
背驰比较相邻同向确认笔：后段创新极值、同向柱面积比 A后/A前 < 0.7。新低伴随动能减弱是候选结构；面积放大不是有效底背驰。
结构背驰 / 宽口径检查是否紧邻已完成中枢并脱离区间；宽口径降分。趋势分类以紧邻中枢及前一个中枢为锚。普通相邻笔衰减与标准结构背驰分开看，不凭名称高估质量。
B1 / S1有效底 / 顶背驰端点。反转候选。现有 V1 不单独交易一类点。
B2 / S2B1 后回调笔不破前低；S1 后反弹笔不过前高。二次确认候选，更关注趋势内回调是否结束。
B3 / S3向上离开中枢后回踩终点仍 > ZG；向下离开后回抽终点仍 < ZD。突破后的回踩/回抽，而不是第一根突破 K 线。

代码依据：chan.py 的 merge_klines、build_bi、build_zhongshu、detect_beichi、find_bsp、analyze；本册不改变原项目规则。

05量化因子字典：哪些真的在用

把因子分为三类：硬条件决定是否保留候选，描述特征帮助解释信号，扩展因子留待独立验证。原始指标的方向各不相同；所有“质量评分”仍统一为越高越好。

因子计算 / 取值当前用途
方向一致性4H 最新收盘价相对中枢：上方 long、下方 short、内部或结构不足 neutral；笔方向影响强度描述。硬条件 信号方向必须相同，中性不通过。V1 不另设强度分门槛。
信号类型与活跃度仅 B2/B3/S2/S3，k_idx 位于最近两个确认笔端点范围。硬条件 选最新支持类型；失败不回退挑旧信号。
锁定状态信号端点之后已有新的确认笔；locked 必须明确 true。硬条件 false 或缺失都拒绝。
结构距离d=|信号极值价−关键位|/信号极值价。硬条件 至少一个结构位满足 d≤tol。
波动容差tol=0.6×mean((H−L)/C)，使用最近 20 根已收盘 4H。硬条件 波动越大容差越宽；这是平均相对振幅，不是 ATR。
结构失效多：现价≤信号价×0.998；空：现价≥信号价×1.002。硬条件 已破失效位就观望，不为凑单放宽止损。
可达结构目标顺方向最近的 4H ZG/ZD 或上下笔端点。硬条件 无目标拒绝；EMA 不是 V1 目标来源。
预计净盈亏比对入场、止损、目标估算不利滑点，计双边交易手续费。硬条件 ≥2。当前尚未计历史资金费。
MACD 柱面积比后同向笔面积 / 前同向笔面积。上游结构 <0.7 支持背驰与 B1/B2 的形成；并非所有 B3 都要求背驰。
回撤深度与量能回调幅度 / 推进幅度；回调笔单位 K 均量与推进笔比较。评分特征 用于 B2/B3 原始评分；V1 不另加量能硬门槛。
DIF / RSI / KDJ 确认信号处及当时已经可见的附近 K 线指标。分析已有 页面用于确认票；不作为当前 V1 独立开仓条件。
常规 / 隐藏背离价格与 MACD柱、DIF、RSI、KDJ、量能的拒绝同创新极值。分析已有 常规≥2票，隐藏≥3票；V1 不接 DB/DS。
综合评分 q页面单级别 q=方向×0.4+信号×0.4+确认×0.2。页面解释 不是胜率；不拿页面 70% / 100% 当账户投入比例。
信号唯一性hash(inst, bar, type, 极值时间)，同回放只发一次候选。研究去重 不依赖滚动窗口 k_idx；执行阶段还需持久化抢占。
点差与盘口深度(卖一−买一)/中间价；预计数量对应的盘口冲击。待接入 先作为成交成本过滤；不是已验证方向因子。
资金费率 / 结算时间真实合约费率、下一次结算时间、持仓方向。待接入 用于持仓成本；不能只看当前费率代替历史结算。
未平仓量 / 主动买卖流OI 变化、主动买卖成交差等。待研究 需要新数据源；现有 K 线量价不能冒充真实资金流。
V1 的组合方式是“逐项通过”，没有一条神奇总分。锁定、顺势、靠近结构、止损有效、有目标、净盈亏比合格必须同时满足。任何一个硬条件失败，输出观望。高 RSI 确认分不能覆盖已经失效的止损。

如何验证因子，而不是越加越多

  1. 固定原始结构和成本假设，保留一套基准规则；按时间划分参数选择区间和未参与选择的测试区间。
  2. 每次只新增或移除一个过滤条件，比较扣费后的每笔期望、回撤、交易数量与稳定性。锁定和时间对齐属于正确性要求，不拿“使用未来数据”的版本做可部署候选。
  3. 价格、EMA、MACD 同源性强，多票不等于多份独立证据。扩展测试数量也要记录，避免只挑表现最好的一次。
  4. 减少信号数量不自动说明质量提高；锁定更慢也可能损害入场价格。没有完整成交回测前，只能先比较信号行为。

06成本与盈亏比：动手算一次

下面的教学计算器复现 V1 的手续费/滑点公式。它只检查价格与成本，不检查缠论结构、账户风险或资金费，也不会下单。默认费率是代码中的研究假设，不是你的欧易账户费率。

d = +1（做多）或 −1（做空）
E = 参考价 × (1 + d × 滑点率)
L = 止损触发价 × (1 − d × 滑点率)
T = 目标价 × (1 − d × 滑点率)
每单位预计损失 = d × (E − L) + 费率 × (E + L)
每单位预计收益 = d × (T − E) − 费率 × (E + T)
预计净盈亏比 = 预计收益 / 预计损失

试着把目标改近，或把滑点从 0.05% 提高到 0.20%，观察毛盈亏比看似合格时，净盈亏比如何变化。

07仓位风控：先定最多亏多少

信号决定“有没有交易理由”，风控决定“最多能承担多少”。两层必须分开。杠杆只影响保证金占用，不把已经算好的风险数量再乘一次。

本单风险预算 = min(权益 × 单笔比例, 权益 × 组合比例 − 已有未平仓风险)
初步张数 = 风险预算 / 每张含费用与滑点的预计损失
最终张数 = 按 lotSz 向下取整(min(初步张数, 保证金可承受张数, 名义仓位上限, 最大委托量))
项目当前代码默认 / 设计值实现边界
单笔风险权益的 0.5%独立风险函数已有，可传入参数。
组合风险权益的 1%函数需要调用者提供已有风险，不自动查询账户。
持仓数量最多 2 笔函数需要调用者提供 open_positions。BTC/ETH 同方向相关风险仍需组合审查。
杠杆 / 名义仓位默认 3 倍；本单名义金额≤权益×1仅风险测算，不等于已经在欧易设置杠杆。
日 / 周亏损3% / 6% 暂停新增仓位设计待实现；界面开关不具备真实熔断功能。
强平与维持保证金需真实账户模式、持仓档位和合约规则尚未建立完整模型。结构止损应留有强平前的充足缓冲。

一个已经用代码核算的教学案例

权益与可用保证金均 10,000 USDT，计划成交价 2,000，止损 1,960，每张假设为 0.1 个基础币，lotSz/minSz 假设 0.01 张，最大委托量假设 10,000 张。单笔风险 0.5%、单边费率/止损滑点均 0.05%、杠杆 3 倍。

RISK BUDGET

50.00 USDT

最终数量 11.63 张，即 1.163 个基础币。模型预计止损损失约 49.96 USDT。

MARGIN & NOTIONAL

2,326.00 USDT

名义价值约 2,326 USDT；保证金加双边费用预留约 777.66 USDT。它不是风险预算。

合约规格只是教学假设，不代表当前 ETH 或 BTC 的真实规格。风险函数的 entry 是计划成交价，应在调用前包含适当入场滑点；它不会再自动添加开仓滑点。

风险预算不是亏损保证。跳空、盘口不足、止损保护失败可能让实际损失超出预算。数量小于最小张数就放弃，不向上取整凑单；同向高度相关品种也不能视为互相分散。

欧易永续委托量使用张数，需要按具体合约类型、面值与计价币种换算，并遵守数量与价格步长。欧易合约参数与交易接口。当前风险函数仅支持已核实每张基础币数量的线性 USDT 合约，不适用于反向合约。

08MySQL 数据库与订单执行设计

部署使用 MySQL 8.0.16+、InnoDB、utf8mb4；本地无数据库服务时可用 SQLite。数据库的首要职责是恢复事实、复现研究、避免重复操作。

研究表（已建表逻辑）保存内容
quant_runsrun_id、状态、配置、代码哈希、数据哈希、统计摘要。
quant_candles按 run_id 保存该次回放的输入 K 线，确保可复查。
quant_signal_observations每次看到信号时的极值时间、锁定状态与原始快照。
quant_evaluations每个收盘事件的行动、拒绝原因、价格计划和时间水位。
quant_schema_migrations迁移文件与校验和；已应用文件不可直接覆盖修改。

每个收盘事件的观察与决策同事务提交。MySQL 建表会产生隐式提交（官方说明），迁移不能假装整体可回滚；当前初始建表采用可重试语句和迁移锁。研究库 MySQL 实例联调仍待完成。

  • 部分成交：按实际已成数量保护，撤单后仍确认累计成交量。
  • 止损失败：暂停新单、撤销剩余入场部分，并尝试只减仓退出；断网时不能承诺立即平仓。
  • 程序重启：先对账持仓、订单、保护单与账户权益，再恢复新增仓位。
  • 暂停开仓：继续维护已有止损；“全部平仓”必须是另一个明确动作。

欧易 clOrdId 的唯一性检查主要覆盖未完成订单，本地必须长期保持唯一并记录请求状态。欧易订单管理指南。不能把一次 HTTP 成功响应当成全部成交，更不能当成止损保护已经生效。

09验收标准与下一步

01 / RESEARCH

先证明时序正确

相同历史前缀追加未来数据后，过去决策不变；预热、窗口、数据缺口和信号重绘有记录。能解释每次候选和拒绝。

02 / BACKTEST

再证明扣费后有效

加入撮合、退出、资金费、未成交和净值。检查样本外期望、回撤、交易数量，以及成本变差后是否仍有优势。

03 / DEMO

验证交易执行

测试下单超时、部分成交、撤单竞态、断线重连、数据库中断、保护失败和熔断；逐项核对欧易账单。

04 / LIVE

小资金逐步验证

执行模型与策略研究均通过后，才接实盘。阈值由可承受回撤和真实样本决定，不以固定几天运行作为盈利证明。

为什么不先把买点直接接到下单 API？

现有页面与量化过滤口径不同，且最新信号可能未锁定。直接连接容易重复下单、使用过期价格、缺失保护单，并且无法用真实成交验证策略。

为什么 V1 不用所有指标一起投票？

相同价格数据派生的指标高度相关；增加参数会提高筛选历史最佳结果的机会。先固定可解释基线，再用独立样本验证新增因子的贡献。

为什么合成 demo 跑通仍然不能说明策略赚钱？

合成行情只验证代码、时间推进和数据库流程。当前没有真实成交模型，也没有资金费与净值账本，候选信号数不能转换成收益率。
